Documentation

Everything about Yonder

How to install it, set it up the way you like, and hack on it. If something here is unclear or out of date, open an issue — docs fixes are very welcome.

Getting started

Yonder is a small desktop app that reminds you to take short breaks from your screen. Once installed, it lives in your system tray (Windows, Linux) or menu bar (macOS) and counts down to your next break.

  1. Install Yonder for your platform (see Installation).
  2. Launch it. On first run a three-step setup asks for your language, a break mode and skip difficulty, then a break style and smart pause. You can skip it and change everything later.
  3. Keep working. About 30 seconds before a break, a small toast appears. When the break starts, the break screen fades in with a countdown.
  4. Check in by clicking the tray icon (Windows, macOS): a small popover shows the live countdown, today's screen time, breaks taken and screen score, with buttons to take a break now, pause (30 minutes, 1 hour or until tomorrow), skip the next break or open settings. It closes when you click elsewhere or press Esc. Right-click the icon for the classic menu. On Linux, where many panels don't report tray clicks, the menu has a Show status entry that opens the same popover.
  5. Tweak it any time from Settings in the popover or the tray menu.

Settings are grouped into pages: Overview, Breaks, Break screen, Wellness reminders, Smart pause, Schedule, Shortcuts & automation, Stats and General.

Yonder has no account and no telemetry. All settings and stats are stored locally in your user profile.

Installation

Download the latest installer from the releases page. Builds are roughly 10 MB because Yonder uses Tauri and your system's built-in webview instead of bundling a browser.

Windows

Run the .exe (NSIS) setup or the .msi installer. Windows 10 and 11 are supported; the required WebView2 runtime ships with Windows 11 and is installed automatically on Windows 10 if missing. If SmartScreen warns about an unrecognized app, choose More info → Run anyway.

Prefer not to install anything? Download Yonder_<version>_x64-portable.zip, unzip it anywhere and run yonder.exe. Settings still live in your user profile.

macOS

Open the .dmg and drag Yonder into Applications. Universal builds run natively on Apple Silicon and Intel. If macOS blocks the first launch, right-click the app and choose Open.

Linux

Use the .AppImage (make it executable with chmod +x), or install the .deb / .rpm package for your distribution. A tray requires a desktop with StatusNotifier / AppIndicator support (most do; on GNOME install the AppIndicator extension).

Debian / Ubuntu (apt). Install from the signed APT repository and get updates through apt upgrade:

curl -fsSL https://rmoura98.github.io/yonder/apt/yonder.gpg | sudo tee /usr/share/keyrings/yonder.gpg > /dev/null
echo "deb [signed-by=/usr/share/keyrings/yonder.gpg] https://rmoura98.github.io/yonder/apt stable main" | sudo tee /etc/apt/sources.list.d/yonder.list
sudo apt update && sudo apt install yonder

Verify a download

Every release includes SHA256SUMS.txt. Put it next to the file you downloaded and run sha256sum -c --ignore-missing SHA256SUMS.txt on Linux or shasum -a 256 -c --ignore-missing SHA256SUMS.txt on macOS. On Windows, compare (Get-FileHash .\Yonder_*_x64-setup.exe).Hash with the matching line.

Start at login

Enable Settings → General → Launch at login so Yonder is always ready.

Countdown next to the tray icon

On macOS (and in some Linux panels) the time until your next break is shown beside the tray icon. If you prefer an icon-only menu bar, turn off Settings → General → Show countdown next to the icon; it takes effect immediately. Windows can't show text beside a tray icon, so the setting is hidden there (the countdown stays in the icon's tooltip).

On Windows, turn on Settings → General → Show countdown in the icon (off by default) and the tray icon itself shows the time until your next break: minutes ("12"), then seconds with an underline in the last minute, or hours ("2h") when more than 99 minutes remain. During a break, or while paused, the normal icon returns. It follows the light or dark taskbar, and the tooltip still has the full text.

Break modes

A mode is a preset for how long you work between breaks and how long each break lasts. Pick one to start, then adjust any value in Settings.

ModeWorkBreakGood for
Balanced20 min20 sEveryday screen work; follows the 20-20-20 rule.
Deep Focus45 min30 sLong, focused sessions. Adds a longer stretch break every few cycles.
Eye Care15 min15 sTired or dry eyes; frequent, tiny pauses.
Wellness25 min45 sTime to stand up, stretch and breathe.

Long breaks can be enabled for any mode: choose how often (for example every 4th break) and how long (for example 5 minutes).

Skip difficulty

Sometimes you genuinely can't take a break. Skip difficulty decides how easy it is to dismiss one:

  • Casual — a Skip button is always visible.
  • Balanced — the Skip button appears after a few seconds, giving you a moment to reconsider.
  • Firm — you can skip, but only by holding the Skip button (or Esc) for 2 seconds while a fill sweeps across it, so an impulsive click never skips. The tray menu and skip shortcut are also ignored during a break, except in the Gentle and Notification styles where there is no button to hold.
  • Hardcore — no skipping; the break runs its full length.

Set it in Settings → Breaks. When skipping is allowed, pressing Esc during a break ends it (twice in a row; in Firm, hold it).

Skipped breaks are counted separately in Stats, so you can see how often you skip.

Reminders

Before every break Yonder gives you a heads-up, in one of two styles (Settings → Heads-up):

  • Next to the cursor (the default) — a small “Break in 0:54” follows your pointer for a few seconds (5 seconds to a minute, your choice), then fades away. It's click-through and never takes the keyboard; snooze or skip from the tray menu, the popover or the shortcuts.
  • Card — a frosted card near the top of the screen with Start break now, +1m / +5m / +15m and Skip.

In both styles the last five seconds count down next to the cursor (“Starting break in 5…1”), and the heads-up appears on the screen you're using. You can change the lead time, or turn the heads-up off entirely. If you're typing when a break is due, Yonder waits a few seconds for a natural pause before starting.

Smart pause

Smart pause automatically holds your reminders when a break would be disruptive. Each rule can be toggled on or off in Settings → Smart pause. All detection happens locally from simple system signals; smart pause never records audio or video.

Meetings & callsMicrophone or camera in use by any appMicrophone or camera in use by any app (read from CoreAudio and CoreMediaIO; no permission prompt), plus Zoom's meeting helperActive microphone recording via PulseAudio / PipeWire
FullscreenGames, presentations and fullscreen video in browsers and playersAny app running fullscreen on a displayNot yet
Do Not Disturb / FocusFocus assist / Do not disturb is onFocus is on, read from macOS's Do Not Disturb database when Yonder has Full Disk Access (not possible on every macOS version)GNOME Do Not Disturb, or notifications inhibited on desktops such as KDE
Screen sharing & recordingA known recorder is open (OBS, Streamlabs, XSplit, Camtasia and similar), or displays are duplicatedA known recorder is open (OBS, ScreenFlow, Camtasia and similar), or displays are mirroredA known recorder is open, or a PipeWire screencast is active
Focus appsThe active app's process name is on your focus-apps list (e.g. a DAW or a video editor)
Idle detectionTime since the last keyboard or mouse input. After you've been away long enough, the break timer resets — stepping away counts as a break. On Linux this works on X11 (needs xprintidle), GNOME, KDE Plasma, and Wayland compositors that support the ext-idle-notify-v1 protocol (Sway, Hyprland, river, Wayfire, niri and others). If your compositor supports none of these, away time isn't detected.

Screen sharing. Windows and macOS offer no way to ask which app is capturing the screen, so Yonder cannot see a Teams, Zoom or Meet screen share directly. Those calls are normally held by the microphone/camera rule. The recorder list matches apps that are open, not only while they record.

When a smart pause ends, Yonder gives you a short grace period before the next break rather than jumping straight in.

When a break is due in a fullscreen app. By default a fullscreen app holds the break until you leave it. When a break is due in a fullscreen app lets you choose instead: Wait until I leave fullscreen (the default), Show a quiet notification instead (a native notification, no break window; the break is counted as skipped and the timer starts over), Show the break anyway, or Skip this break (dropped silently, counted as skipped). The choice only applies to fullscreen apps: calls, Do Not Disturb, screen sharing and focus apps always hold breaks, and wellness reminders stay held while a fullscreen app is in front.

Hold limit. If something keeps smart pause on for a long time (an app that never releases the microphone, a fullscreen window left open), the break goes ahead anyway after Hold breaks for at most: 30 minutes, 1 hour (the default), 2 hours or never. The heads-up then says you've been busy for a while.

What's holding it. While a break is held, the Today page and the tray popover say why, naming the app when Yonder can tell (for example you're in a call (Discord) on Windows, or the fullscreen game). Once the break is due, the countdown shows Due and the status says when it will start: right after the activity ends, or after Wait after the activity ends (1, 2 or 5 minutes), and at the latest when the hold limit is reached. Chat apps such as Discord keep the microphone open for as long as you're in a voice channel, even muted; turn off Meetings & calls or lower the hold limit if you'd rather get your breaks then.

Office hours

Office hours limit reminders to the times you actually work. Under Settings → Schedule, enable office hours and set a start and end time for each weekday. Days without hours are treated as days off.

Outside office hours the tray icon dims and no breaks or wellness reminders are shown. You can still start a break manually whenever you like.

Planned breaks

Planned breaks are recurring blocks such as lunch or a daily walk. Add one with a name, a time, a duration and the days it repeats on.

  • Yonder won't schedule a regular break right before a planned one.
  • When a planned break starts, you get a friendly notification; the timer resets when it ends.

Focus sessions

A focus session is an optional Pomodoro-style mode that runs alongside your eye breaks. Start it from the tray (Start focus session), from the Today page, or from Settings → Focus session; stop it the same way. There is also a shortcut you can assign under Keyboard Shortcuts (none by default).

By default a session is four focus periods of 25 minutes. After each one comes a 5 minute focus break, and after the fourth a 15 minute long focus break, which ends the session. Focus breaks use the normal break screen, titled Focus break or Long focus break. The Today page shows where you are, for example Focus 2/4 · 12:30 left. All lengths, and the number of focus periods per session, are set on the Focus session page.

How it works with eye breaks

  • Your eye-break schedule keeps running during a session. If an eye break would land within the merge window (3 minutes by default) of a focus break, it is folded into that focus break, so you get one interruption instead of two. An eye break that is further away still happens as usual.
  • A focus break counts as a break and restarts the eye-break countdown.
  • A session only counts active screen time. It waits while you are away, paused, outside office hours, or held back by smart pause, the same way regular breaks do.
  • When the last focus break ends, or when you stop the session, the normal eye-break schedule carries on. Stopping during a focus break lets that break finish.
  • Skipping a focus break (when your skip difficulty allows it) moves the session on to the next focus period.
  • Hooks receive focus as YONDER_BREAK_KIND for focus breaks.

A session is not remembered across restarts: it ends when Yonder quits.

Wellness & custom reminders

Besides screen breaks, Yonder can nudge you about small habits — configure them in Settings → Wellness reminders. The built-in reminders are posture and blink, each with its own interval.

Custom reminders

Create up to 5 custom reminders. Each one has a title, an optional message, an icon, a sound and an interval. Reminders appear as small, non-blocking cards at the top of the screen.

Create new offers a few presets to start from: Warm compress, Eye drops, Glare & airflow check, Drink water and Stand up & stretch, or a blank reminder. They're comfort tips, not medical advice, and you can change anything after adding one.

When reminders are due together

Yonder shows one reminder at a time. If several come due at once, only the one that has waited longest since it last appeared shows; the others skip to their next turn. With the defaults (posture every 30 minutes, blink every 15), that means one reminder every 15 minutes, never two. Reminders set to Stay until done are never skipped: they wait their turn, and while one waits for you, newer ones collect in a small orb showing how many are waiting.

Evening filter

An optional filter that warms and dims your screen in the evening, in Settings → Evening filter. It is off by default.

  • Schedule — turn on Turn on in the evening and pick a From and To time (the default is 21:00 to 07:00; the end can be after midnight). The filter fades in after the start time and out after the end time over the Fade over period (30 minutes by default, or no fade).
  • Strength — a Color temperature slider (2700–6500 K, default 3400 K; 6500 K means no tint) and a Dimming slider (0–60%, default 10%). Preview shows the filter at full strength for a few seconds and then puts the screen back.
  • Tray menu — Turn on evening filter / Turn off evening filter flips it right away, even when the schedule is off. The choice lasts until the schedule next starts or ends.

How it works on each system

  • Windows — Yonder sets the gamma ramp of every display. Windows refuses ramps that are too dark or too far from normal, so the filter is limited to about 3400 K with light dimming: warmer settings look the same, and if a display still refuses, Yonder retries with a milder ramp.
  • macOS — Yonder sets the display transfer tables through CoreGraphics. macOS also drops them by itself when Yonder exits.
  • Linux (X11) — Yonder sets the RandR gamma of each display. Wayland has no gamma interface for ordinary apps, so the filter is unavailable there and the page says so; GNOME's Night Light and KDE's Night Color do the same job.

Because it works on the display's color tables, nothing is drawn over your windows: clicks and focus are not affected. Don't run another color filter (f.lux, Night Light, Night Shift) at the same time, since they would fight over the same tables.

It never stays stuck on

The screen is restored when you quit Yonder. While the filter is on, Yonder keeps a small marker file; if Yonder is killed or crashes, the next start sees it and resets the display to normal before doing anything else. The filter also re-applies itself every 30 seconds in case another program resets the display. Times are fixed clock times; a sunset-based schedule is not available.

Break screen styles

Choose how the break screen looks in Settings → Break screen:

  • Animated — Aurora, Nebula or Ripple: slow, calming motion behind the countdown.
  • Gradient — a preset or your own two-color gradient.
  • Image — any image file from your computer.
  • Blurred desktop — your own screen, frozen and softly frosted behind the countdown, then sharpening back as the break ends. Windows, macOS and Linux (X11, GNOME and KDE Wayland; if a screenshot cannot be taken, the backdrop is shown).
  • Split screen — your desktop splits open across the middle, top half up and bottom half down, to reveal a texture: linen, felt, cork, cutting mat or brushed steel. Windows, macOS and Linux (X11, GNOME and KDE Wayland; if a screenshot cannot be taken, the backdrop is shown).
  • Gentle — no takeover: every display dims around a small countdown and clicks pass through, so a call, a video or a game keeps going. The break window never takes focus, so skip it from the tray menu or with the skip shortcut (CtrlAltS by default). All platforms.
  • Notification — no break window at all: a native desktop notification and the break sound when the break starts, then it simply ends after the break length. It counts as a taken break when the timer runs out. The heads-up and cursor countdown still apply; skip it from the tray or the skip shortcut. You may need to allow notifications for Yonder in your OS settings. All platforms.

Blurred desktop and split screen take a snapshot of your screen when the break starts. It's used only for the break screen and never leaves your computer.

Multiple monitors. Every display gets its own break screen, and the blurred and split styles use that display's own picture, whatever its position or scaling. The skip and end buttons and the sound are on your primary display only; Esc or the tray ends the break everywhere. The heads-up, the cursor countdown and wellness reminders appear on the display your mouse is on. If you plug in or unplug a display during a break, its break screen is added or removed; a display added mid-break shows the plain backdrop rather than a snapshot.

You can also choose a break sound (soft synthesized chimes and tones, your own audio files added in Settings → Sounds, or silence), adjust its volume, and write your own custom messages to rotate through. Turn on Pause music and video during breaks (Settings → Screen breaks → More) to pause what's playing when a break starts and resume it afterwards; Yonder only resumes what it paused. It uses the system media controls on Windows, Music and Spotify on macOS, and playerctl on Linux. Animations are disabled automatically when your OS requests reduced motion.

Guided exercises

Off by default. Turn on Guided exercises during long breaks (Settings → Break screen → Exercises) and long, planned and focus breaks show a calm step-by-step routine under the message, sized to the break: slow blinks, a dot to follow with your eyes (left and right, up and down, a figure eight), near and far focus, a neck stretch, shoulder rolls and a minute of palming (warm palms resting over closed eyes). Each step has a short instruction and a "2 of 8" indicator; the countdown stays in view. A 5 minute break runs all eight steps; shorter ones use eye exercises only, and very long breaks repeat the routine. If sounds are on, a soft chime marks the end of palming. Also during short breaks adds a brief eye-only routine to the regular breaks.

Exercises appear on the full screen and split screen styles. Gentle and Notification breaks never show them. With reduced motion enabled, the illustrations are still pictures with the instruction. The exercise ideas come from the exercise lists of Workrave and Safe Eyes (and break ideas from Stretchly); the wording and illustrations are Yonder's own. They are general wellness suggestions, not medical advice: skip anything that hurts.

Keyboard shortcuts

Global shortcuts work from any app: Take a break now, Pause / resume, Skip next break and Start / stop focus session. None is set by default, because a global shortcut takes its keys away from every other app. Set the ones you want in Settings → Keyboard Shortcuts: click a shortcut and press a combination. The × next to it (or Backspace) unsets it.

Before 1.0.11 they defaulted to Ctrl Alt B / P / S (⌘ ⌥ on macOS). Updating clears those defaults once; shortcuts you picked yourself stay.

Inside a break, Esc skips / ends the break when your skip difficulty allows it.

Automation

Under Settings → Shortcuts & automation you can set a shell command (a hook) that runs when a break starts, ends or is skipped. Useful for pausing music, changing your chat status or dimming smart lights. The command receives these environment variables:

VariableValue
YONDER_EVENTbreak-start, break-end or break-skip
YONDER_BREAK_KINDThe kind of break (for example a regular or a long break)
YONDER_BREAK_SECSThe break's length in seconds
 
# Linux / macOS: pause media during breaks
if [ "$YONDER_EVENT" = "break-start" ]; then
  playerctl pause
else
  playerctl play
fi
Commands run with your user's permissions. Only add commands you understand.

Scripting & automation

You can control a running Yonder from a script, a launcher, a macro tool or another app, in two ways that do the same thing: yonder:// links and command-line options. If Yonder isn't running yet, it starts and then carries out the command.

What it doesCommand lineLink
Start a break now (optional length in minutes, 1 to 120)--break or --break 5yonder://break or yonder://break/5
End or skip the break in progress (honors your skip difficulty)--end-breakyonder://end-break
Skip the next break--skipyonder://skip
Postpone the next break (minutes, 1 to 120, default 5)--snooze 10 (or --postpone)yonder://snooze/10
Pause reminders for some minutes (1 to 1440), or until resumed if no number is given--pause 30 or --pauseyonder://pause/30 or yonder://pause
Pause until tomorrow--pause-tomorrowyonder://pause-tomorrow
Resume reminders--resumeyonder://resume
Pause if running, resume if paused--toggle-pauseyonder://toggle-pause
Start a focus session (optional work length in minutes, 1 to 240, for this session only)--focus or --focus 50yonder://focus or yonder://focus/50
Stop the focus session--focus-stopyonder://focus-stop
Start or stop the focus session--focus-toggleyonder://focus-toggle
Restart the countdown to the next break--resetyonder://reset

Links also accept the number as a query, such as yonder://pause?minutes=30. Options can be combined (--pause 30 --verbose) and --pause=30 works too. Anything unknown or out of range, such as --pause 0 or a typo, is ignored and noted in the log; it never opens a window. Starting Yonder with a command, or with --background, doesn't open Settings. Yonder can't be quit or locked this way, and links can't change your settings.

Windows

Yonder is a windowed app, so it prints nothing to the terminal; it just acts. The installer puts it in %LOCALAPPDATA%\Yonder.

# PowerShell or Command Prompt
start yonder://pause/60
& "$env:LOCALAPPDATA\Yonder\yonder.exe" --break

; AutoHotkey v2: Win+Shift+P pauses for an hour
#+p::Run "yonder://pause/60"

The links work after installing with the .exe installer, which registers the yonder:// scheme for your account. The portable zip can't register it, so use the command-line options there (they work everywhere).

macOS

# Terminal, Raycast, Alfred, Hammerspoon ...
open "yonder://pause/60"
/Applications/Yonder.app/Contents/MacOS/yonder --break

In the Shortcuts app, add an Open URLs action with yonder://break, then run it from the menu bar, a keyboard shortcut or an automation (for example, pause when a Focus turns on). Use the executable path above rather than open -a Yonder --args, which is ignored when Yonder is already running. macOS learns about the link scheme the first time Yonder is opened from the Applications folder.

Linux

yonder --pause 30
xdg-open "yonder://break/5"
./Yonder_x.y.z_amd64.AppImage --skip

# cron: pause during your Monday stand-up, resume after
0 10 * * 1 DISPLAY=:0 yonder --pause 30
30 10 * * 1 DISPLAY=:0 yonder --resume

The .deb and .rpm packages register the yonder:// scheme and put yonder on your PATH. An AppImage registers the scheme for itself the first time it runs (run it again if you move the file). Scripts started from cron or systemd need DISPLAY (X11) or WAYLAND_DISPLAY and DBUS_SESSION_BUS_ADDRESS set to reach the running instance.

Any web page can offer a yonder:// link, and your browser asks before opening it. That's why only break and timer controls are available through links: the worst a stray link can do is start or skip a break.

Stats

The Stats view shows today's screen score, a 14-day chart, a weekly summary, your streaks and a heatmap of the past year. It's meant as a gentle mirror, not a scoreboard.

Weekly summary

This week compares the last 7 days with the 7 before: breaks taken, breaks skipped, screen time and adherence, the share of due breaks you took (natural breaks count as taken). Breaks that were due are estimated from your screen time and your current work interval, the same way the screen score is.

Streaks

A good day is a day where you took at least 80% of the breaks that were due. The current streak counts good days in a row up to today, and the best streak is the longest run Yonder has recorded. Days with no screen time (a weekend, a holiday) don't break a streak, and neither does today until it's over.

Past year heatmap

One square per day for the last 52 weeks, weeks running Monday to Sunday. Darker means a higher share of due breaks taken; an empty square is a day with no screen time. Hover a square for the date, breaks taken and skipped, and adherence. Month and weekday names follow the app language.

Export and reset

Stats are stored only on your machine, about a year of daily history in stats.json. Open Settings → Stats and use Export CSV (one row per day, ISO dates and seconds, for spreadsheets), Export Markdown (a readable journal table, newest first, in your language) or Export JSON (the raw file) to save a copy, or Reset to start fresh.

Restarts & backups

Restarting Yonder

Yonder saves a small snapshot of your countdown (time worked, snoozes, the short-break count, a pause and the reminder timers) about once a minute and when you quit. If you restart it within 10 minutes, for an update or a crash, the countdown carries on from where it was; the time it was closed counts as time away, so if that was as long as your reset after being idle setting it counts as a natural break and the countdown starts again. An older snapshot is ignored, and a break that was in progress is never resumed. The snapshot is state.json in the app data folder, next to stats.json.

Back up and restore settings

Open Settings → About → Backup. Export settings… downloads a .yonder.json file with all your settings, your custom sounds and your break background image. Import settings… reads such a file, checks it, and after a second click replaces your current settings. Stats are not included. Importing on a new computer restores everything, but note that a backup made by a newer Yonder can't be read by an older one.

Logs & troubleshooting

Yonder always keeps a small log file that helps explain what happened when something misbehaves. It records start-up (version, operating system, language), settings that couldn't be read, why smart pause kicked in (fullscreen, a call, Do Not Disturb, screen sharing, and the name of the app responsible), breaks starting, ending, skipped or postponed, update checks, scripting commands, and failures to detect something on your system. It never records what you type, window titles, files or anything on your screen; at most it names an app or process. Nothing is sent anywhere.

SystemLog folder
Windows%LOCALAPPDATA%\app.yonder.desktop\logs
macOS~/Library/Logs/app.yonder.desktop
Linux~/.local/share/app.yonder.desktop/logs

Open it from Settings → About → Troubleshooting → Open logs folder. The current file is yonder.log; when it reaches about 350 KB it becomes yonder.1.log, then yonder.2.log, and the oldest is deleted, so the logs stay near 1 MB in total.

More detail

By default Yonder logs at info level. For a bug that's hard to pin down, turn on Detailed logging in Settings → About → Troubleshooting, or start Yonder with --verbose, then reproduce the problem. That adds the checks behind each decision, such as which smart-pause detectors ran. Turn it off afterwards; it only makes the file rotate faster.

Reporting a bug

Please attach yonder.log (and yonder.1.log if the problem is older) to your GitHub issue. It's plain text, so skim it first if you like; there's nothing in it you'd need to remove.

Building from source

Yonder is built with Tauri 2: a Rust core with a web-based UI rendered by the system webview.

Prerequisites

  • Rust (stable), installed via rustup
  • Node.js 20+ and npm
  • Platform webview and build dependencies as listed in the Tauri prerequisites guide (WebView2 + MSVC build tools on Windows, Xcode Command Line Tools on macOS, WebKitGTK and friends on Linux)

Run in development

git clone https://github.com/RMoura98/yonder
cd yonder/app
npm install
npm run tauri dev

Build an installer

npm run tauri build

Installers are written to app/src-tauri/target/release/bundle/.
